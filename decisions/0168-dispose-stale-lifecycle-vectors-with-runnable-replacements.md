## Context

Decision [0066](0066-published-esm-versions-are-frozen.md) freezes published ESM bytes and revisions. The reference lifecycle runner correctly leaves three V36 `Collect` specifications waiting at the explicitly named `Final` wait; the frozen fixture instead expects completion (Cratis/Screenplay#1366). Cratis/Screenplay#1134 (PR #1350) corrected the runner before this vector's expectations were superseded. V51–V57 each omit the required `OrderPacked.parcelId` from two appended lifecycle facts, following commit `87f743839` in PR #1274 (Cratis/Screenplay#1367). The runner correctly rejects those facts. These are stale fixture expectations, not changes to language admission or execution semantics.

The user's direct authorization in Addendum 2 accepts the narrow disposition and replacement policy below. It neither permits rewriting published fixtures nor authorizes publication, a push, or GitHub mutations.

## Decision

- Preserve every original full/minor/extension vector, hash and semantic revision. `Get(36)` and `Get(51)` through `Get(57)` retain their original meanings. Do not allocate a new language or ESM version for fixture corrections.
- Publish `EsmGoldenVectors.LifecycleDispositions` as immutable, machine-readable per-specification outcomes. Each entry identifies the original vector, semantic version/revision, exact byte SHA-256, lifecycle owner kind/name, specification, complete ordered failure messages, reason and replacement vector identity. An entry supersedes only that exact lifecycle execution expectation. It never relaxes strict deserialization, revision checking, normalization, canonical serialization or hashing.
- Publish `LifecycleV36R2` with only the three `Collect` terminal expectations corrected from `completes` to `waits Final`, plus its recomputed revision. Publish `LifecycleV57R2`, derived from V57, with only the two missing `parcelId` payload values, using each appended fact's existing parcel event-source identity, plus its recomputed revision. V57's runnable replacement covers all fourteen V51–V57 dispositions; seven otherwise-equivalent replacements are unnecessary.
- Discover every public corpus vector entry, including aliases and named replacements, alongside integer and minor goldens. Strictly admit each and execute every declared lifecycle specification exactly once. Non-disposed results and all replacement results must pass. Disposed results must fail exactly as recorded. Missing results, new or changed failures, unexpectedly passing originals, duplicate/unused entries, missing replacements and disposition cycles fail the specs.
- Regenerate replacement bytes only through the production serializer in an explicit opt-in spec path. Regeneration deliberately fails so generated bytes, fresh revisions and hashes must be reviewed and pinned before a clean passing build and run.

## Consequences

Portable consumers can distinguish frozen admission/serialization contracts from runnable lifecycle acceptance fixtures without handwritten version exceptions. The disposition table contains exactly seventeen narrowly identified failures, not a waiver for entire versions. New lifecycle-bearing vectors are covered automatically. The reference runner, grammar, compilers, CLI, MCP, editors, samples and `.play` authoring behavior are unchanged; no AI corpus change is needed.
